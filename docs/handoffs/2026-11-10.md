A phone call cannot run the browser front desk's tools, because no page holds the call's connection. - **The live self-test passes 22 of 22 against the real bridge.** Through the phone path, who is working, how many decisions are open and which is first, and whether the box is healthy each equal the bridge's own answer, in 18, 954 and 879 milliseconds. The gateway's record and the bridge's log name the same answers by hash. A real question went through the phone path to the live commander pane and its words came back in the same simulated call.
- **Who may use it is decided before a request body is read.** Two headers: a conversation id this machine registered when it dialled, and a key of 256 random bits made up for that one call and stored only as a hash. Anything else gets the same 404 a dead address gives. An inbound call is never registered, so it gets no tools.
- **Nothing can be changed by phone.** Write tools are refused at the gateway and a second time inside the bridge. A question to the commander is fenced: the commander only, three per call, no word that reads as an action, no path, link or secret.
- **The door is one process and it has never been opened.** It starts the gateway, a throwaway tunnel and a hold on sleep, and it closes with the call, on a failed dial, and by itself after 23 minutes. Its whole sequence was run against a stand-in for the vendor: 7 scenarios pass, including a dial that fails and a dial that returns no conversation id.
- **An attacker and a reviewer checked it, on copies.** Held: nothing was served without the call's key, no write tool was reachable, no path or host trick worked. Found and fixed, each with a test: questions arriving at the same moment slipped past the per-call limit (12 reached the commander's pane; now 3); the check that a question is in the owner's own words did not read the vendor's documented format; the grading script passed a call in which the machine could not be reached; the after-call wait stopped at 15 minutes of a 20-minute call.

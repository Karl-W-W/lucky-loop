## PRINCIPLES

- **A check must prove the result belongs to this run.** The first live question through the phone path
  passed in a second and a half on a three-day-old answer to a different question. Now a rule.
- **An unattended session reads and proposes; plain code applies a closed list.** Judging what a session
  wrote is open-ended, and two checks proved it. A session that cannot write, plus a script that can do
  four things, is a design a checker can finish checking.
- **A design that fails two independent checks on new holes gets dropped, not patched a third time.**
- **A fence is a fact about one tool version, so it carries its own proof.** The laptop runs a newer
  version than the box, and a flag the first two builds relied on does not exist on the box.
- **Clean and pushed is not the same as loses nothing.** A worktree's own history log dies with it.
- **A word is not an act.** One decision the owner made five weeks ago was never carried out, because a
  safety check refused the agent and the paste went into a report nobody read again. The department
  summary found it. A refused act is the owner's paste, and it needs its own card.
- **Propose the durable home first.** For anything meant to run unattended, the box version is the first
  proposal, with what it needs from the owner.
- **Every script that acts needs an explicit verb.** A fixer ran a script with `--help` and it ran for
  real. It now needs `--tick`, and refuses to run on the laptop at all.
